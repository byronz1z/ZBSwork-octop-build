> 本文是公开版，只写代码/仓库层面的去向。生产、密钥、证书相关的处置记录在私有 service 库 `docs/迁移处置清单.md`。

## 1. 为什么迁移

旧体系（WorkBuddy 主导，2026-09-24 ～ 10-06）的问题【实测核对】：

| 问题 | 证据 |
|---|---|
| 在 fork 上长分支开发，上游升级要整线 rebase | `zbs/base` 73 文件改动混在一条线上 |
| 漏记在用功能：桌面云壳（默认连公司服务器） | 旧模块册 19 条里没有；`zbs/base`、r2 两条线都不含 |
| 虚构模块：SRV-3“中文字体” | 上游 Dockerfile 本来就装 `fonts-noto-cjk` |
| 条目数自相矛盾 | 文字总结称 20 条，`modules.json` 与模块册实为 19 条 |
| 冒名 tag：fork 上的 `v1.0.2b6` 不是上游 b6 | 指向 `264244a8`（rebuild/base），上游真 b6 为 `eb280112` |
| CI 改动全在 fork 的工作流上 | 跟随上游时每次都要合并工作流冲突 |

## 3. 新旧分流规则

- **旧事项**：只读归档，不再推进。确有价值的，由总控**重新判层、重写任务书**后作为新 Issue 登记——不沿用旧编号、旧结论。
- **新事项**：一律按 [协作规范](协作规范.md)：Issue → 分支 → PR → CI → 验收。
- 引用旧材料时必须标注“旧体系·未复核”，复核后才能当事实使用。
